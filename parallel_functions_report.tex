\section{Introduction}

This report documents the design decisions and performance considerations for the parallel implementation of three core functions in the order book processing system: \texttt{updateDisplay}, \texttt{totalAmountTraded}, and \texttt{printOrderStats}. Each function has been optimized using OpenMP parallel programming techniques to improve performance over their sequential counterparts.

\section{Function Analysis}

\subsection{updateDisplay Function}

\paragraph{Design Decisions:}
The parallel implementation uses a multi-phase approach: (1) parallel decode and count, (2) prefix-sum for grouping, (3) parallel processing, and (4) parallel file writing.

A compact \texttt{SnapshotStock} struct (3 bytes: 2 for stockID, 1 for spread) minimizes memory footprint. Thread-local counting arrays avoid contention during the counting phase. Stock entries are grouped using parallel prefix sums, and each snapshot's data is processed independently. Output uses buffered \texttt{FILE*} with \texttt{fwrite} for fast I/O, with parallel snapshot file generation.

\subsection{totalAmountTraded Function}

\paragraph{Design Decisions:}
The \texttt{totalAmountTraded} function implements a straightforward parallel reduction pattern using OpenMP's built-in reduction clause. The design prioritizes simplicity and efficiency by leveraging the \texttt{\#pragma omp parallel for reduction(+:total)} directive.


\subsection{printOrderStats Function}

\paragraph{Design Decisions:}

Each thread maintains its own section of a flat array (\texttt{allThreadStats[thread\_id * MAX\_STOCKS]}) using a compact \texttt{StockStatsCompact} struct. Since stock IDs are bounded ($\leq$100,000), fixed arrays provide O(1) access without hash overhead. After parallel processing, the merge phase is also parallelized across stock IDs using \texttt{\#pragma omp parallel for}, with chunking (\texttt{schedule(static, 2048)}) for cache efficiency. Output uses buffered \texttt{FILE*} with \texttt{fwrite}.
